# explore-mobile — 제품 문서

> 최종 갱신: 2026-07-29 · HEAD `79231f0` (branch `master`)
> 이 문서는 `.moai/project/interview.md`의 답변(Stage A/B)과 코드베이스 실측을 근거로 작성되었다. 수치가 실행 결과인지 문서 기록인지는 각 절에서 구분해 표기한다.

## 1. 이것은 무엇인가

`explore-mobile`은 **모바일 기기(Android/iOS)를 제어하는 에이전트-비의존적(agent-agnostic) CLI**다. AI 에이전트나 자동화 스크립트가 하나의 안정적인 **JSON 입출력 계약**만으로 에뮬레이터·시뮬레이터·실기기를 조작할 수 있게 하는 것이 목적이며, 최종 목표는 멀티 기기 상호작용을 포함한 모바일 테스트 자동화다.

핵심 정체성은 세 가지다.

1. **JSON in/out 계약** — 모든 명령은 stdout에 JSON 문서를 정확히 1개 찍고, 프로세스 종료 코드를 그 결과에 맞춘다(`0`=성공, `1`=실패). 자유 텍스트 출력은 없다. 성공은 `{"ok":true,"command":"<name>","data":{...}}`, 실패는 `{"ok":false,"command":"<name>","error":{"code":"...","message":"...","details":{...}}}` 형태로 고정된다.
2. **원시 동작(primitive) 계층** — CLI는 "무엇을 누르고 어디를 스와이프하는지"만 책임진다. "지금 어떤 화면인지 판단"하거나 "실패하면 어떻게 재시도할지"는 CLI의 일이 아니다(§4 범위 참조).
3. **플랫폼 차이 흡수** — 공통 요소 스키마(`CommonElement`)와 `DeviceBackend` 인터페이스를 통해 Android(adb)와 iOS(idb)가 같은 명령 표면을 공유한다. 호출자는 `--device <serial>`만 넘기면 되고, 어느 플랫폼인지 몰라도 된다.

## 2. 누구를 위한 것인가

- **1차 사용자 — AI 에이전트/자동화 스크립트.** JSON in/out 계약(§3)은 정확히 이 사용자를 위해 설계되었다. 화면을 스크래핑하지 않고, 구조화된 응답을 파싱해 다음 행동을 결정한다.
- **2차 사용자 — 그 에이전트를 운용하는 사람.** `doctor`/`reset`(환경 부트스트랩)과 사람이 읽는 오류 메시지·`README.md`는 이 사용자를 향한다.
- **현재 팀 구성**: `solo` — 단독 유지, 현재 사용자는 없음(인터뷰 Stage B 답변). 즉 지금은 사전 조율 없이 API/계약을 바꿀 수 있는 시기이지만, JSON 계약 고정(§4-3)은 그 자유와 무관하게 처음부터 지켜야 할 규율로 명시되어 있다.

## 3. 핵심 계약 — 왜 이 방식인가

에이전트가 CLI를 신뢰하고 자동화 루프에 넣으려면, 출력 형태가 매번 달라지거나 사람이 읽게 포맷팅된 텍스트를 파싱해야 한다면 실패한다. 그래서 이 프로젝트는 처음부터 세 가지를 불변식으로 못박았다(자세한 코드 근거는 `tech.md` §제약 참조):

- **조용한 성공 금지** — `ok:true`이면서 기기에 아무 효과가 없는 응답은 결함이다. 2026-07-29 하루에 고친 실기기 결함 5건 중 4건이 이 부류였다(`launch`의 암시적 인텐트 미해결, IME 바인딩 경쟁, 키보드 숨김이 자신이 방금 보낸 입력을 지움, 미연결 기기를 연결로 계수). 이 규율의 실무적 함의는 **mock 테스트가 검증할 수 있는 범위의 한계**다 — mock은 "어떤 argv가 구성되었는가"까지만 검증하고, "기기가 그 argv를 어떻게 해석했는가"는 검증하지 못한다. 효과·타이밍·화면 변화는 실측(실기기/실시뮬레이터) 판정이 필요하다.
- **의존성 최소화** — 런타임 의존성은 정확히 1개(`fast-xml-parser`)다.
- **JSON 입출력 계약 고정** — 위 §1의 형태가 전부다. 이 계약이 깨지면 에이전트 연동 자체가 무너진다.

## 4. 명령어로 보는 기능

12개 명령이 사용자 대면 기능 표면이다(`src/cli/router.ts`의 `COMMANDS` 레지스트리 기준, 실행 확인). 아래는 구현 세부가 아니라 **에이전트가 무엇을 할 수 있는가**의 관점이다.

| 분류 | 명령 | 제공하는 능력 |
|---|---|---|
| 탐색 | `devices` | 연결된 기기 목록(시리얼·모델·OS·연결 상태·에뮬레이터 여부) |
| 앱 생명주기 | `launch <package>` / `stop <package>` | 패키지/번들 시작·강제 종료 |
| 화면 관찰 | `screenshot [--out]` / `dump [--web]` | PNG 캡처 · 공통 스키마로 정규화된 UI 트리(네이티브 또는 iOS 웹 페이지 DOM) |
| 입력 | `tap` / `key` / `text [--web]` | 좌표/셀렉터 탭 · 키 이벤트 · 텍스트 입력(ASCII/한글/이모지 자동 판별) |
| 제스처 | `swipe` / `scroll` | 좌표 간 스와이프(원시) / 방향·비율 기반 스크롤(편의 계층, 이동 최소 문턱 검증 포함) |
| 환경 | `doctor [--yes\|--install] [--clean]` / `reset` | 플랫폼 도구 설치 진단·부트스트랩(동의 기반) / 사전 상태 복원 |

`dump`/`tap`/`text`는 `--web` 플래그로 iOS 시뮬레이터의 **웹 페이지 콘텐츠**(네이티브 접근성 트리에는 없는 영역)에도 도달한다.

## 5. 범위 경계 — IN과 OUT

인터뷰(Stage A Round 3)에서 확정된 경계이며, 로드맵(§7)의 모양이 이 경계로부터 도출된다.

**IN (CLI 책임)**
- 기기 제어 원시 동작: tap / swipe / scroll / text / key / dump / screenshot / launch / stop
- 플랫폼 차이 흡수: 공통 요소 스키마 + `DeviceBackend` + 레지스트리 라우팅
- JSON 입출력 계약
- 환경 부트스트랩·정리: `doctor` / `reset`

**OUT (에이전트 책임)**
- 탐색 루프(다음에 무엇을 할지 결정)
- 재시도 전략
- "지금 어떤 화면인지"의 판단(화면 상태 해석)
- 테스트 시나리오 저장·리포팅

이 경계의 실무적 함의: `scroll`이 화면이 실제로 움직였는지 확인하지 않고 제스처만 보내는 것(호출자가 `dump`로 재확인)이나, `swipe`가 지속시간 생략 시의 신뢰성 문제를 감추지 않고 그대로 노출하는 것은 버그가 아니라 이 경계를 지키는 설계 결정이다(`README.md` `scroll`/`swipe` 절 참조).

실기기/실시뮬레이터 검증은 SPEC 4건(SPEC-ANDROID-001/IOS-001/WEBVIEW-001/GESTURE-001, 모두 `status: completed` — `spec.md` frontmatter 실측)이 진행되며 순차적으로 넓어졌다. 검증된 것과 검증되지 않은 것을 모두 기록한다(CHANGELOG.md/README.md `Status` 절 기준 — 문서 기록).

**검증됨**
- iOS 시뮬레이터 전체 Safari 여정(2026-07-26, iPhone 17 Pro / iOS 26.0)
- iOS `--web` 경로(2026-07-27, 같은 시뮬레이터)
- iOS/Android 제스처(`swipe`/`scroll`)(2026-07-27 iOS, 2026-07-28 Galaxy S25 Ultra)
- 나머지 Android 명령 전부(`tap`/`text`/`key`/`stop`/`doctor`/`reset`/`screenshot`/`dump`) + ADBKeyBoard 런타임 다운로드(2026-07-29)

**의도적으로 검증하지 않음(이유 포함)**
- `power`/`volume_up`/`volume_down` 키 별칭 — 화면을 끄거나 볼륨을 바꾸는 것은 얻는 커버리지 대비 나쁜 트레이드오프로 판단
- 멀티 기기 격리 — 물리적으로 연결된 기기 2대가 필요
- AC-GEST-020(`--duration` 생략 경로의 신뢰성) — 본질적으로 간헐적(측정 결과 10회 중 8회 성공 수준)이라 PASS로 승격하지 않음
- AC-GEST-021 실기기 재현 — 미해결 공백으로 남음
- Android 일반화 — 기기 1대·밀도 1개를 넘어선 다른 기종/제조사/OS 버전은 미측정

**알려진 미해결 상태**
- `--web` 프록시 세션이 연속 호출 간 불안정(완화책: `--page <n>` 명시 + 호출 간 간격)
- `adb`가 없는 호스트에서는 `doctor`가 조기 반환하여 iOS 섹션 전체(iOS 전용 사용자 포함)에 도달하지 못함
