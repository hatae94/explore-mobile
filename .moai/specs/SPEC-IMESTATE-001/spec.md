## §A. 개요 (Context & Goal)

### A.1 배경 — 점검이 남긴 갭

로드맵(`.moai/project/product.md:101`)의 "SPEC-04 — 탐색 루프 + 멀티 기기 시나리오 오케스트레이션"은 **신규 기능 항목이 아니었다.** `interview.md:39`가 탐색 루프·재시도 전략·화면 판단을 **OUT**(에이전트 담당)으로 못박았고, `interview.md:43`이 그 파급을 기록해 두었다:

> SPEC-04는 신규 기능 SPEC이 아니라 **"두 기기 상호작용에 필요한 원시 동작이 이미 충분한가"를 점검하는 성격**이 된다.

그 점검을 2026-07-29에 실행했다. 두 기기 시나리오("기기 A를 조작 → 기기 B에서 결과 확인")가 요구하는 능력을 현행 코드와 대조한 결과, **10가지가 이미 충족되어 있었다**:

| 필요 능력 | 충족 근거 |
|---|---|
| 두 기기 동시 발견·구분 | `devices`가 adb+idb 목록을 병합. `DeviceInfo`(`src/schema/device-backend.ts:90-103`)가 `serial`·`model`·`osVersion`·`platform`·`isEmulator`·`connectionState` 제공 |
| 명령별 기기 지정 | `--device <serial>` — `devices`를 제외한 **11개 명령 전부** `resolveTargetDevice` 사용 |
| 엉뚱한 기기 조작 방지 | 2대 이상 연결 + `--device` 생략 → `AMBIGUOUS_DEVICE`, 첫 기기를 임의 선택하지 않음(`device-targeting.ts:92-103`) |
| 크로스플랫폼 라우팅 | `BackendRegistry` 파사드가 시리얼→소유 백엔드로 위임 |
| 화면 읽기 | `dump`(공통 `CommonElement`), `screenshot` |
| 조작 | `tap` `text` `key` `swipe` `scroll` |
| 앱 제어 | `launch` `stop` |
| 동시 `dump` 파일 충돌 | 기기측 임시 경로에 시리얼 + **랜덤 접미사**(`adb-backend.ts:49-59`, REQ-MULTIDEV-004) |
| 스크린샷 파일 충돌 | 기기측 임시 파일 자체가 없음 — `adb exec-out` 스트리밍, 호스트 경로는 `--out`으로 호출자 지정 |
| 한글 입력 첫 호출 삼킴 | `waitForImeBindingReady`가 IME 전환 **후** · 입력 **전**에 대기(`adb-backend.ts:388, 464, 647`) |

이 중 **동시 실행을 명시적으로 겨냥해 설계된 것은 `dump`의 랜덤 접미사 하나뿐**이다(`adb-backend.ts:49-54`가 "even concurrent `dump` invocations targeting the SAME serial from separate CLI processes never race"라고 진술 — **동일** 시리얼까지 방어 대상으로 삼는다). 스크린샷의 무충돌은 스트리밍 설계의 부수 결과이고(`screenshot.ts:4-8`은 동시성을 언급하지 않는다), IME 바인딩 대기는 **단일 기기 콜드 경로의 타이밍 결함** 대응이다(`adb-backend.ts:386-397`). 0.1.0은 이 세 항목을 모두 "동시 실행을 겨냥한 설계"로 귀속했으나 3중 2가 사실과 달랐다.

**무방어 공유 자원은 둘 남았다** — IME 세션 저장소와 웹 캘리브레이션 캐시다. 이 SPEC은 그중 **유실 비용이 조용한 복원 불가로 직결되는 IME 세션 저장소**를 닫고, 다른 하나는 §C.4로 이월한다. `src/backend/ime-session-store.ts:22-27`의 `@MX:NOTE`가 전자를 직접 서술한다:

> read-modify-write is NOT atomic across concurrent writers: two `AdbBackend` processes racing to establish sessions for two **DIFFERENT serials** at the same instant could clobber each other's write (last write wins, dropping the other's entry). This is an accepted, pre-existing limitation (best-effort persistence, not a distributed lock) — the common case, one CLI invocation at a time, is unaffected.

즉 **이 결함은 새로 발견된 것이 아니라, 코드가 스스로 기록해 둔 채 "일반적인 경우에는 무영향"이라는 전제 아래 수용된 것**이다. 이 SPEC이 여는 근거는 결함의 발견이 아니라 **그 전제의 소멸**이다: 두 기기 시나리오는 정의상 "한 번에 한 CLI 호출"이 아니다.

#### 결함 ① 시리얼 간 유실 (0.1.0이 식별)

비-ASCII(한글·이모지) 텍스트를 입력하려면 `AdbBackend`가 기기의 기본 IME를 ADBKeyBoard로 전환하고, 나중에 `reset`이 복원할 수 있도록 "전환 직전의 IME"를 기록해 둔다. 매 CLI 호출이 **별개의 OS 프로세스**이므로(`ime-session-store.ts:5-11`) 이 기록은 디스크에 남아야 하고, 현재는 **모든 기기가 공유하는 단일 파일** `<cache-dir>/ime-sessions.json`에 `{ [serial]: { originalIme } }` 형태로 저장된다.

두 기기에 병렬로 비-ASCII 텍스트를 입력하면, `setOriginalIme` **내부의** read-modify-write가 겹친다:

```
프로세스 A (기기 A)                프로세스 B (기기 B)
setOriginalIme 진입                setOriginalIme 진입
  readAll() → {}                     readAll() → {}
  sessions[A] = {...}                sessions[B] = {...}
  writeAll({A})  ────────┐           writeAll({B})  ────────┐
                         └───────────────────────────────────> 나중 쓰기가 이김
디스크 최종: { B: {...} }           ← A의 기록이 사라졌다
```

#### 결함 ② 동일 시리얼 경합 (0.2.0이 편입 — 감사 지적)

기기별 파일 분리는 결함 ①만 없앤다. **같은 기기에 `text`를 동시에 두 번** 호출하면 그 기기의 파일은 여전히 하나이고, `adb-backend.ts:454-457`이 check-then-act이다:

```ts
const existingOriginal = await this.imeSessions.getOriginalIme(serial);
if (existingOriginal === undefined) {
  await this.imeSessions.setOriginalIme(serial, currentIme);
}
```

두 프로세스가 모두 `undefined`를 읽고 모두 쓴다. 그런데 바로 위 주석(`:446-452`)은 이 가드의 목적을 명시한다 — *"recording ADBKeyBoard itself as 'the original' is the exact cross-process bug this fixes"*. **그 가드가 정확히 이 경합에 무너진다**: 늦게 진입한 프로세스가 이미 ADBKeyBoard로 전환된 기기의 IME를 "원래 IME"로 기록하고, `reset`은 기기를 **ADBKeyBoard 자체로 복원**한다.

사용자에게 보이는 결과가 결함 ①과 **동일**(복원 불가)하므로 같은 SPEC에서 닫는다. 그리고 `deviceDumpPath`가 **동일 시리얼 동시 호출을 실재하는 시나리오로 간주해 방어**하는 프로젝트에서, IME 경로만 그것을 무시할 근거가 없다.

#### 사용자에게 보이는 결과 (양쪽 공통)

**기록이 유실되거나 잘못 기록된 기기는 `reset`을 실행해도 원래 IME로 복원되지 않는다.** 실기기에는 ADBKeyBoard가 활성 키보드로 남아 사람이 직접 손으로 되돌려야 한다. 오류도 나지 않는다 — 조용한 실패다.

### A.2 목표 (WHY)

두 기기 시나리오에서 각 기기의 IME 복원 기록이 **다른 기기의 동시 작업 때문에도, 같은 기기의 동시 작업 때문에도** 유실되거나 오염되지 않게 한다. 목표는 레이스가 발생했을 때 잘 처리하는 것이 아니라, **레이스가 성립할 수 없게 만드는 것**이다 — 시리얼 간에는 공유 자원을 제거해서(REQ-001), 동일 시리얼에는 조건부 쓰기를 단일 원자 연산으로 만들어서(REQ-007).

부차 목표: 이 변경이 기존 단일 기기 동작을 바꾸지 않는다. 프로덕션 호출자(`AdbBackend`)와 간접 호출자(`reset.ts` · `doctor.ts`)는 수정하지 않는다.

### A.3 확정된 설계 결정 (USER-APPROVED — FIXED)

2026-07-29 사용자 승인(①~④는 초기 승인, ⑤~⑥은 감사 반영 승인). 구현 단계에서 재논의 대상이 아니다.

**① 기기별 파일 분리로 공유 자원을 제거한다**

단일 `ime-sessions.json`을 버리고, 시리얼마다 전용 레코드 파일을 쓴다:

```
<cache-dir>/ime-sessions/<encoded-serial>.json
```

서로 다른 시리얼은 서로 다른 파일을 쓰므로 read-modify-write가 겹칠 대상 자체가 없다. **레이스를 감지·직렬화하는 것이 아니라 성립 불가능하게 만드는 선택**이다.

구 파일 `<cache-dir>/ime-sessions.json`(파일)과 신규 `<cache-dir>/ime-sessions/`(디렉터리)는 이름이 달라 대소문자 무구분 파일시스템에서도 공존한다 — 이관 기간에 둘이 충돌하지 않는다.

**② 파일 락(lock)을 도입하지 않는다**

단일 파일을 유지하고 배타 잠금으로 직렬화하는 대안은 기각한다. 이유: 잠금 자체가 상태가 되어 ① 프로세스가 죽어 남긴 부생 잠금(stale lock)의 통과 기준 ② 대기 상한 ③ 대기 초과 시 산출 계약 — 셋을 모두 새로 정의해야 하고, 그 중 ③은 **"CLI는 절대 멈추지 않는다"는 기존 계약과 정면으로 부딪히는 새 실패 경로**를 만든다. ⑤·⑥이 잠금 없이 남은 두 경합을 닫으므로, 이 기각은 사각지대를 남기지 않는다.

**③ 원자적 쓰기(임시 파일 → rename)만으로는 결함 ①이 고쳐지지 않는다 — 오답으로 명시 기각**

`rename(2)`의 원자성은 "파일이 반쯤 쓰인 상태로 관측되지 않음"만 보장한다. 두 프로세스가 각자 `{}`를 읽고 각자 자기 항목만 담은 **전체 맵**을 쓰는 구조는 그대로이므로, 나중 쓰기가 여전히 앞선 기록을 덮는다. 이 오답은 흔하므로 SPEC 층위에 기각 근거를 남긴다.

**④ 파일명 인코딩은 `adb-backend.ts:57`의 것을 재사용하지 않는다**

```ts
const safeSerial = serial.replace(/[^A-Za-z0-9_-]/g, "_");   // 재사용 금지
```

이 변환은 **손실이 있다**: `192.168.1.5:5555` → `192_168_1_5_5555`. `dump`의 기기측 경로에서는 무해하다(기기마다 파일 시스템이 독립이고 랜덤 접미사가 붙는다). 그러나 IME 기록을 기기별 파일로 쪼개는 데 쓰면 **서로 다른 두 시리얼이 같은 파일명으로 매핑될 수 있고, 그 순간 고치려던 결함이 그대로 재현된다** — 위치만 단일 파일에서 파일명 충돌로 옮긴 셈이다. 두 시리얼이 실제로 같은 값으로 붕괴함을 실행으로 확인했다(§C.1-⑨). REQ-002가 대체 규칙을 정의한다.

**⑤ 동일 시리얼의 "부재식 기록"은 단일 원자 연산으로 만든다 (잠금 없음)**

레코드 파일 생성을 **배타 생성**(`O_CREAT|O_EXCL` 계열 — Node의 `wx` 플래그)으로 수행한다. 파일이 이미 있으면 생성이 실패하고, 그때는 **먼저 기록한 쪽의 값이 이긴다**(덮어쓰지 않는다). 이것이 `adb-backend.ts:454-457`의 "부재일 때만 쓴다"를 원자적으로 만든다.

read-modify-write가 아니라 **단일 시스템 콜의 원자성**에 의존하므로 잠금이 필요 없고 ②와 충돌하지 않는다. 대기·타임아웃·부생 상태가 없으므로 "CLI는 멈추지 않는다" 계약도 유지된다.

**⑥ `clear`는 파일을 지우지 않고 툼스톤(음성 기록)을 남긴다**

`clearOriginalIme(serial)`은 그 시리얼의 **툼스톤 마커**를 만든다. 조회 규칙은 3단계다:

```
1. <enc>.json 이 있으면          → 그 값
2. 없고 <enc>.cleared 가 있으면  → undefined  (구 파일 폴백 억제)
3. 둘 다 없으면                  → 구 파일 폴백 (이관 대상)
```

툼스톤이 구 파일 폴백을 억제하므로 **이관 창 좀비가 닫힌다** — 이관이 끝나기 전에 `clear`가 끼어들어도, 이후 조회가 구 파일에서 그 기록을 되살릴 수 없다. 툼스톤은 레코드 파일과 **다른 경로**이므로 ⑤의 배타 생성과 간섭하지 않는다(새 세션 시작 시 레코드 파일을 배타 생성하고 툼스톤은 멱등하게 제거한다).

0.1.0 §C.2는 이 창을 "닫으려면 §A.3-②가 기각한 잠금이 다시 필요해진다"며 허용된 한계로 두었다. **그 주장은 미검증이었고 틀렸다** — 툼스톤의 쓰기 주체는 해당 시리얼 하나뿐이므로 잠금 없이 닫힌다. 이 SPEC의 존재 근거가 "이전에 수용된 한계가 사실은 본상이었다"인데, 닫을 수 있는 한계를 다시 수용하는 것은 같은 실패를 반복하는 일이다.

```
교체:      ImeSessionStore                      (내부 저장 배치 + 쓰기 원자성)
   ↓
교체:      <cache-dir>/ime-sessions.json         (단일 파일)
        →  <cache-dir>/ime-sessions/<enc>.json    (기기별 레코드, 배타 생성)
        +  <cache-dir>/ime-sessions/<enc>.cleared (기기별 툼스톤)
```

`ImeSessionStore`의 공개 메서드 3개(`getOriginalIme` · `setOriginalIme` · `clearOriginalIme`)는 시그니처가 바뀌지 않는다.

## §B. 요구사항 (GEARS)

> 패턴 라벨: **Ubiquitous**(항상) · **Event-driven / When**(사건) · **State-driven / While**(상태 지속) · **Optional / Where**(조건부 기능) · **Unwanted / If-Then**(원치 않는 상황).
> REQ-004의 `If/Then` 표기는 GEARS 정규 부정형(`shall not`) 대비 레거시 표기이며 백워드 호환 창(2026-11-22) 내에서 유효하다.

### B.1 기기별 격리 (REQ-IMESTATE)

**REQ-IMESTATE-001 — 시리얼 간 공유 자원 제거** *(Ubiquitous)*

시스템은 각 기기의 IME 세션 기록을 그 시리얼 전용 파일에 저장한다. **서로 다른 두 시리얼**의 기록은 어떤 순간에도 같은 파일을 대상으로 read-modify-write 하지 않는다.

- 검증 가능 형태: 서로 다른 시리얼 2개에 대해 `setOriginalIme`을 수행한 뒤, 두 기록이 각각 다른 경로에 존재하고 **양쪽 모두 조회된다.**
- 계보: 이 요구는 REQ-MULTIDEV-003(`adb-backend.ts:246, 445`)과 REQ-INPUT-004(`ime-session-store.ts:2`)가 도입한 크로스프로세스 세션 추적을 강화한다.
- 동일 시리얼 경합은 이 요구의 범위가 아니다 — REQ-007이 담당한다.

**REQ-IMESTATE-002 — 파일명 인코딩은 단사이며 대소문자 무구분 파일시스템에서도 안전하다** *(Ubiquitous)*

시리얼 → 파일명 변환은 세 성질을 모두 만족한다:

1. **단사(injective)**: 서로 다른 시리얼은 항상 서로 다른 파일명으로 매핑된다. 충돌은 없다.
2. **대소문자 무구분 안전**: 파일명 대소문자를 구분하지 않는 파일시스템에서도 성질 1이 성립한다 — 변환 결과는 **단일 대소문자 계열**만 사용한다.
3. **파일시스템 안전**: 경로 구분자(`/` `\`), 콜론(`:`), 그 밖의 예약 문자를 남기지 않으며, 캐시 디렉터리 하위를 벗어나는 경로를 생성하지 않는다.

확정 규칙: **파일명 = 시리얼의 UTF-8 바이트를 소문자 16진수로 인코딩한 문자열**, 확장자는 레코드 `.json` / 툼스톤 `.cleared`. 16진수는 단사이고(역변환 가능), 소문자로 고정하므로 성질 2를 만족하며, `[0-9a-f]`만 쓰므로 성질 3을 만족한다.

- 길이: hex는 입력의 2배이므로 파일명 255바이트 한도에서 시리얼 127바이트까지 안전하다. 실측된 adb 시리얼·iOS UDID는 모두 40바이트 미만이므로 여유가 크다.
- 가독성 손실 보상: 레코드 파일 **내용**에 원본 시리얼을 별도 필드로 기록한다(추적성 목적. 조회 키는 어디까지나 파일명이다).

**REQ-IMESTATE-003 — 구 단일 파일에 남은 살아있는 세션을 잃지 않는다** *(State-driven / While)*

**While** 구 단일 파일 `<cache-dir>/ime-sessions.json`이 존재하고 그 시리얼의 레코드 파일도 툼스톤도 없는 동안, 시스템은 조회 시 구 파일의 기록을 반환한다.

- 왜 필요한가: 이 변경이 적용되는 시점에 ADBKeyBoard가 활성 상태인 기기가 있을 수 있고, 그 복원 기록은 구 파일에만 있다. 구 파일을 무시하면 그 기기는 **영구적으로 복원 불가**가 된다 — 결함을 고치면서 새 결함을 만드는 셈이다.
- 우선순위는 REQ-008의 3단계 조회 규칙이 정한다(레코드 > 툼스톤 > 구 파일).
- 쓰기는 항상 신규 경로로만 한다. **구 파일에는 절대 쓰지 않는다** — 구 파일에 항목별 삭제를 수행하는 설계는 공유 파일 read-modify-write이므로 REQ-001 위반이며 명시적으로 금지된다.
- 이관은 결과적으로 멱등하다: 구 파일의 기록을 신규 레코드 파일로 옮기는 동작이 여러 프로세스에서 겹쳐도, 같은 내용을 같은 경로에 배타 생성하므로(REQ-007) 결과가 같다.
- 이관을 마친 뒤 구 파일은 조회 대상에서 제거된다.

**REQ-IMESTATE-004 — 읽기는 어떤 입력에도 예외를 던지지 않는다** *(Unwanted / If-Then)*

**If** 대상 파일이 없거나, 비어 있거나, JSON으로 파싱되지 않거나, 파싱되지만 기대한 모양이 아니면, **then** 시스템은 "기록 없음"으로 취급하고 `undefined`를 반환한다. 예외를 전파하지 않는다.

- 기존 `readAll`의 동작(`ime-session-store.ts:88-99`)을 기기별 경로에서 그대로 보존한다. 신규 능력이 아니라 **회귀 방지**다.
- 근거: 손상된 세션 기록 하나가 `text`·`reset`·`doctor` 전체를 실패시켜서는 안 된다.

**REQ-IMESTATE-005 — 세션 종료 후 잔재가 남지 않는다** *(Event-driven / When)*

**When** `clearOriginalIme(serial)`이 호출되면, 시스템은 그 시리얼의 레코드를 무효화하고 이후 조회가 `undefined`를 반환하게 한다.

- **"잔재 없음"의 조작적 정의**: 그 시리얼의 **레코드 파일(`<enc>.json`)이 존재하지 않고**, 툼스톤(`<enc>.cleared`)이 존재하며, 조회가 `undefined`를 반환하는 상태. 툼스톤은 잔재가 아니라 REQ-008이 요구하는 **음성 기록**이다.
- 레코드가 애초에 없었다면 조회 결과를 바꾸지 않는다(현행 no-op 의미 보존 — 툼스톤 생성은 멱등하다).

**REQ-IMESTATE-006 — 호출자는 수정되지 않는다** *(Ubiquitous)*

`ImeSessionStore`의 공개 메서드 3개 — `getOriginalIme(serial)` · `setOriginalIme(serial, originalIme)` · `clearOriginalIme(serial)` — 의 시그니처와 반환 계약은 불변이다. 직접 호출자 `AdbBackend`와 간접 호출자 `src/cli/commands/reset.ts` · `src/cli/commands/doctor.ts`(둘 다 `AdbBackend.getTrackedOriginalIme`/`clearTrackedOriginalIme` 경유)는 이 SPEC에서 수정되지 않는다.

- 이 요구는 §D의 제외 항목을 **검증 가능한 형태로 재진술**한 것이다 — 중복은 의도적이며, AC 4건이 여기에 걸린다.
- 테스트 주입 가능성도 보존한다: 경로와 I/O는 계속 생성자로 주입할 수 있어야 하며, 테스트가 실제 `~/.cache`를 건드리지 않는 현재 성질(`ime-session-store.ts:75-86`)을 유지한다.
- I/O 인터페이스에는 배타 생성·삭제·이관용 연산이 **추가**될 수 있다(가법 확장). 기존 `read`/`write`의 시그니처는 바뀌지 않는다.
- 공개 export 표면의 변경 범위는 §C.2에 열거한다.

### B.2 동시성 (REQ-IMESTATE-007 · 008 — 0.2.0 신설)

**REQ-IMESTATE-007 — 동일 시리얼의 부재식 기록은 원자적이다** *(Unwanted / If-Then)*

**If** 같은 시리얼에 대해 두 개 이상의 프로세스가 동시에 "기록이 없을 때만 기록한다"를 시도하면, **then** 정확히 하나만 성공하고 나머지는 **먼저 기록된 값을 보존한다**(덮어쓰지 않는다).

- 확정 기전(§A.3-⑤): 레코드 파일을 **배타 생성**한다. 이미 존재하면 생성이 실패하고, 실패는 오류가 아니라 "다른 프로세스가 이겼다"는 정상 결과로 처리한다.
- 이 요구가 닫는 것: `adb-backend.ts:454-457`의 check-then-act. 그 경합은 늦게 진입한 프로세스가 **이미 ADBKeyBoard로 바뀐 IME를 "원래 IME"로 기록**하게 만들고, 결과는 `reset`이 기기를 ADBKeyBoard로 "복원"하는 것 — 결함 ①과 동일한 증상이다.
- 잠금을 쓰지 않는다: 단일 시스템 콜의 원자성에만 의존하므로 대기·타임아웃·부생 상태가 없다(§A.3-② 무저촉).
- 호출자 `adb-backend.ts:454-457`은 수정하지 않는다(REQ-006) — 저장소가 그 의도를 원자적으로 이행한다.

**REQ-IMESTATE-008 — 무효화된 기록은 되살아나지 않는다** *(Ubiquitous)*

시스템은 무효화(`clear`)된 시리얼의 기록을 어떤 경로로도 되살리지 않는다. 조회는 다음 3단계를 **이 순서로** 따른다:

```
1. 레코드 파일 <enc>.json 존재    → 그 값을 반환
2. 없고 툼스톤 <enc>.cleared 존재 → undefined 반환, 구 파일 폴백 억제
3. 둘 다 없음                     → 구 파일 폴백 (REQ-003)
```

- 이 요구가 닫는 것: 0.1.0 §C.2가 허용된 한계로 두었던 **이관 창 좀비** — 이관 완료 전에 `clear`가 끼어들면 이후 조회가 구 파일에서 제거된 기록을 되살릴 수 있었다. 2단계가 그 부활을 차단한다.
- 툼스톤은 레코드 파일과 다른 경로이므로 REQ-007의 배타 생성과 간섭하지 않는다. 새 세션이 시작될 때 레코드 파일을 배타 생성하고 툼스톤은 멱등하게 제거한다.
- **잠금이 필요하지 않다**: 한 시리얼의 툼스톤을 쓰는 주체는 그 시리얼의 프로세스뿐이며, 생성은 멱등하다.

  | `ImeSessionRecord` | REQ-002가 원본 시리얼 필드를 요구하므로 형태 변경 | 형태 확장 (M2) |
  | `ImeSessionStoreIO` | 배타 생성·삭제 연산 가법 추가 | REQ-006이 명시 허용 |

  이 패키지는 npm에 배포되지 않았고(§C.1-⑩) 명시적 경로를 넘기는 호출자는 테스트뿐이므로 실질 파급은 저장소 내부와 테스트에 한정된다. 다만 미배포가 **열거를 대체하지는 않는다.**
- **iOS는 이 결함과 무관하다** — `idb` 텍스트 입력은 IME 상태를 남기지 않으며(`reset.ts:21-22`), 복원할 세션 개념 자체가 없다. 따라서 이 결함은 **Android 기기 2대** 또는 **Android 1대에 대한 동시 호출**에서만 발생하고, Android 1대 + iOS 시뮬레이터 1대 조합에서는 발생하지 않는다.
- **비-ASCII 입력에만 해당한다** — ASCII 텍스트는 IME 전환 없이 입력되므로 세션 기록이 생기지 않는다.
- **툼스톤은 무기한 누적될 수 있다** — REQ-008의 툼스톤에 만료·정리 규칙을 두지 않는다. 시리얼 수만큼만 생기고 크기가 상수이므로 실무상 누적 비용이 무시 가능하며, 정리 규칙을 도입하면 "언제 지워도 안전한가"라는 새 판단이 필요해진다(그 판단이 틀리면 좀비가 되살아난다). 누적을 택한다.

> 0.1.0 §C.2의 **"이관 창 좀비"** 항목은 삭제됐다 — REQ-008(툼스톤)이 그 창을 닫는다. 함께 있던 **"닫으려면 잠금이 필요하다"**는 진술은 미검증이었고 틀렸으므로 철회한다(§A.3-⑥).

### C.3 검증이 기기를 요구하지 않는다 (설계상 이점)

이 결함은 기기 동작이 아니라 **호스트의 파일 I/O**에서 발생한다. 따라서 서로 다른 시리얼 문자열 2개(결함 ①) 또는 같은 시리얼 문자열(결함 ②)로 두 프로세스를 동시에 돌리는 것만으로 **실제 재현과 실제 수정 확인이 모두 가능하다** — 실기기 2대가 필요하지 않다.

이는 "mock은 argv 너머를 못 본다"는 기존 교훈과 충돌하지 않는다. 그 교훈은 외부 CLI(`adb`/`idb`) 호출 결과를 mock으로 판정할 수 없다는 것인데, 여기서 판정 대상은 외부 CLI가 아니라 **우리가 직접 쓰는 파일**이다. 두 프로세스 실측이 곧 실제 판정이 된다.

단, §C.1의 재현 하네스 관측이 경고하듯 **하네스를 순진하게 짜면 거짓 음성·거짓 실패가 모두 발생한다.** AC-002·003이 하네스 요건을 명시한다.

### C.4 다른 SPEC으로 넘기는 후속 (cross-SPEC follow-up)

- **웹 캘리브레이션 캐시 (`src/webview/calibration.ts`, REQ-WEB-ACT-005)** — `CalibrationStore`가 **같은 결함군**이다: 같은 캐시 디렉터리(`resolveApkCacheDir()`), 단일 공유 파일 `web-calibration.json`, `readAll()` → `all[serial] = record` → 전체 write의 비원자 read-modify-write. 주석 스스로 "mirroring `ImeSessionStore`"라고 적는다. **이월 근거는 피해 등급 차이다** — IME 기록 유실은 사람이 기기를 손으로 되돌려야 하는 복원 불가로 직결되지만, 캘리브레이션 유실 비용은 재측정 1회다. 이월은 정당하나 **미공개는 정당하지 않으므로** 여기에 명시한다. 유실의 실제 재현은 하지 않았다(§C.1-⑳).
- **ADBKeyBoard APK 캐시 디렉터리의 동시 접근** — IME 세션 저장소와 같은 캐시 디렉터리를 공유하지만 다운로드/설치 경로는 별개 자원이며 이번 점검에서 결함을 확인하지 않았다. 별도 점검 대상.
- **탐색 루프 · 재시도 전략 · 화면 판단** — `interview.md:39`의 OUT 경계. 이번 점검에서 그 경계를 바꿀 근거는 나오지 않았다. 에이전트 책임으로 유지.
