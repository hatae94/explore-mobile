# 인수 기준 — SPEC-IMESTATE-001

> 형식: Given-When-Then. 각 AC는 관찰 가능(테스트 출력 / 파일 존재 / 필드 검증 / 명령 출력)해야 한다. 검증 방식은 unit / unit(mock) / unit(실FS) / greppable / git(범위 비교) / e2e(호스트) / e2e·manual / doc-review 중 하나 이상을 명시한다.
>
> **원칙(SPEC-IOS-001에서 확립)**: 관측하지 않은 것을 PASS로 기록하지 않는다.
>
> **이 SPEC 고유의 원칙 ①**: AC-002는 **수정 전에 FAIL이 관측되어야** 이후의 PASS가 의미를 갖는다. 수정 전 FAIL 관측 기록이 없으면 PASS로 인정하지 않는다.
>
> **이 SPEC 고유의 원칙 ② (0.2.0 — 감사 반영)**: "없음"을 확인하는 검사는 **양성 대조를 동반**해야 한다. 패턴이 틀려서 아무것도 매치하지 않는 것과 대상이 깨끗한 것을 구별할 수 없는 검사는 공허하다. 1차 감사에서 AC-008(grep 패턴이 실제로 매치되지 않음)과 AC-018(`git diff`가 커밋 후 항상 빈 출력)이 이 함정에 빠졌고, 둘 다 REQ 보호의 **유일한** 기계적 증거였다.

### AC-IMESTATE-001 — 서로 다른 시리얼은 서로 다른 파일을 쓴다
- **Given** 빈 캐시 디렉터리와 서로 다른 시리얼 `SERIAL-A` · `SERIAL-B`,
- **When** 두 시리얼에 대해 각각 `setOriginalIme`을 수행하면,
- **Then** 두 기록이 **서로 다른 경로**에 저장되고, `getOriginalIme("SERIAL-A")`와 `getOriginalIme("SERIAL-B")`가 **모두** 각자 기록한 값을 반환한다.
- 검증: unit

### AC-IMESTATE-002 — 인터리빙을 강제해도 시리얼 간 기록이 유실되지 않는다 (핵심 AC)
- **Given** 아래 두 요건을 만족하는 테스트 하네스와 서로 다른 시리얼 2개,
- **When** `setOriginalIme` 두 호출의 **내부 읽기가 둘 다 끝난 뒤에야 쓰기가 일어나도록** 강제하면,
- **Then** 두 시리얼의 기록이 **모두** 조회된다.

**하네스 요건 (필수 — 0.2.0 감사 반영)**:
1. **가짜 IO는 경로별로 키를 나눈 저장소여야 한다.** 가짜 디스크를 단일 변수(blob) 하나로 두면, 수정 후 기기별 경로가 달라져도 가짜 IO가 경로를 무시해 **여전히 한쪽이 이긴 것처럼 보인다** → 거짓 실패("수정이 듣지 않았다"로 오독).
2. **인터리빙은 `setOriginalIme` 내부에서 강제해야 한다.** `setOriginalIme`은 자기 안에서 다시 읽으므로, 두 호출을 순차 `await`하는 하네스는 **재현에 실패한다**(거짓 음성 — 실제로 확인됨, `spec.md` §C.1 재현 하네스 관측). 읽기 배리어 등으로 메서드 **안쪽**을 겹치게 해야 한다.
3. **테스트는 경로가 아니라 IO를 주입해 작성한다.** 생성자 arg1의 의미가 M2에서 파일→디렉터리로 바뀌므로, 경로에 의존하면 M1 테스트 본문을 M2에서 수정해야 하고 전후 대조가 서로 다른 두 테스트의 비교로 변질된다.

- **전후 대조 의무**: 이 테스트는 **수정 전 코드에서 FAIL해야 한다**(한쪽 기록 소멸 = `plan.md` §F M1의 게이트). 수정 후 PASS로 전환된 것을 확인한다.
- 검증: unit(mock) + 전후 대조

### AC-IMESTATE-003 — 별개 프로세스 2개가 동시에 써도 양쪽이 살아남는다
- **Given** 빈 캐시 디렉터리와 서로 다른 시리얼 2개,
- **When** 별개 OS 프로세스 2개를 동시에 띄워 각각 자기 시리얼의 세션을 기록하면,
- **Then** 두 프로세스가 끝난 뒤 두 시리얼의 기록이 **모두** 조회된다.
- **판정 하네스**: 빌드 산출물 `dist/backend/ime-session-store.js`를 직접 임포트하는 스크립트 2개를 동시 실행한다(`node --input-type=module`). CLI `text` 명령을 거치지 않으므로 **실기기·adb가 불필요**하다.
- **정직성 조건**: 수정 전 동일 시나리오에서 유실이 관측되지 않았다면, 이 AC는 "유실 부재 확인"까지만 주장하고 "결함 해소 증명"은 주장하지 않는다. 자연 발생 타이밍 유실은 `spec.md` §C.1-⑰의 미관측 항목이므로, 어느 쪽인지 기록한다.
- 검증: e2e(호스트)

### AC-IMESTATE-004 — 특수문자를 포함한 시리얼도 충돌하지 않는다
- **Given** 손실 있는 변환에서 같은 값으로 붕괴하는 시리얼 쌍 `192.168.1.5:5555` 와 `192_168_1_5_5555`(붕괴는 `spec.md` §C.1-⑨에서 실행 확인),
- **When** 두 시리얼에 각각 다른 값으로 `setOriginalIme`을 수행하면,
- **Then** 두 기록이 서로를 덮지 않고 각각 조회된다.
- 이 AC가 실질 가드다 — `spec.md` §A.3-④가 기각한 재사용을 실수로 도입하면 여기서 실패한다. AC-008은 회귀 신호일 뿐이다.
- 검증: unit

### AC-IMESTATE-005 — 대소문자만 다른 시리얼이 분리된다 + 볼륨 특성을 스스로 관측한다
- **Given** 실제 파일시스템 위의 임시 디렉터리와 대소문자만 다른 시리얼 쌍 `ABC123` / `abc123`,
- **When** ① 먼저 볼륨 무구분성을 프로브한다 — `probe` 파일을 만들고 `PROBE` 이름으로 접근 가능한지 확인 ② 두 시리얼에 각각 다른 값으로 `setOriginalIme`을 수행하면,
- **Then** 두 기록이 각각 조회된다.
- **프로브가 필요한 이유 (0.2.0 감사 반영)**: 인코딩이 소문자 hex이므로 두 시리얼은 애초에 다른 파일명이 되고(`414243313233` vs `616263313233`), 따라서 **대소문자 구분 볼륨에서도 이 테스트는 통과한다.** 프로브 없이 PASS로 기록하면 `spec.md` §C.1-⑲의 미관측이 관측으로 부당 승격된다. 볼륨이 무구분이 아니면 그 사실을 skip 이유로 기록하고 §C.1-⑲를 미관측으로 유지한다.
- 검증: unit(실FS)

### AC-IMESTATE-006 — 파일명에 예약 문자가 남지 않는다
- **Given** 경로 구분자와 콜론을 포함한 시리얼,
- **When** 파일명 인코딩을 적용하면,
- **Then** 결과 파일명에 `/` · `\` · `:` 가 없고, 결합된 경로가 캐시 디렉터리 하위를 벗어나지 않는다.
- 검증: unit

### AC-IMESTATE-007 — 레코드 내용으로 어느 기기인지 알 수 있다
- **Given** 임의의 시리얼,
- **When** 그 시리얼의 세션을 기록한 뒤 레코드 파일 내용을 읽으면,
- **Then** 내용에 **원본 시리얼**이 필드로 포함되어 있다.
- 근거: 파일명이 hex라 사람이 읽을 수 없으므로 추적성을 내용으로 보상한다(REQ-002). 조회 키는 파일명이며 이 필드는 조회에 쓰이지 않는다.
- 검증: unit

### AC-IMESTATE-008 — 손실 있는 정리 코드를 재사용하지 않았다 (양성 대조 필수)
- **Given** 구현 완료 상태,
- **When** 아래 **두 명령을 순서대로** 실행하면,
- **Then** ①은 매치가 **있고**(양성 대조 — 패턴이 유효함을 증명), ②는 매치가 **없다**.
```bash
# ① 양성 대조 — 패턴이 실제로 동작함을 먼저 증명한다
grep -nF 'replace(/[^A-Za-z0-9_-]/g' src/backend/adb-backend.ts
# 기대: :57 매치 (exit 0)

# ② 본 검사
grep -nF 'replace(/[^A-Za-z0-9_-]/g' src/backend/ime-session-store.ts
# 기대: 매치 없음 (exit 1)
```
- **`-F`(fixed-string)가 필수인 이유 (0.2.0 감사 반영)**: 0.1.0은 BRE 이스케이프 형태(`'replace(/\[^A-Za-z0-9_-\]/g'`)를 썼고, 실행하면 `exit=1`로 **아무것도 매치하지 않는다**(실측). 그 상태에서는 손실 있는 변환을 그대로 복사해 넣어도 이 AC가 PASS한다 — 방지하려는 결함을 감지할 수 없는 공허한 검사였다.
- 이 AC는 **회귀 신호**이며 실질 가드는 AC-004다. 다른 표기의 손실 변환(예: `/[^\w-]/g`)은 이 검사를 통과하므로 AC-004가 최종 판정을 담당한다.
- 검증: greppable

### AC-IMESTATE-009 — 구 파일에만 있는 기록도 조회된다
- **Given** 그 시리얼의 레코드 파일도 툼스톤도 없고, 구 단일 파일 `ime-sessions.json`에 `SERIAL-A`의 기록만 존재하는 상태(변경 직후, ADBKeyBoard가 활성인 기기가 있는 경우),
- **When** `getOriginalIme("SERIAL-A")`를 호출하면,
- **Then** 구 파일에 기록된 값이 반환된다.
- 이 AC가 막는 것: 결함을 고치면서 **기존 활성 세션을 영구 복원 불가로 만드는** 새 결함.
- 검증: unit

### AC-IMESTATE-010 — 레코드 파일이 구 파일보다 우선한다
- **Given** 같은 시리얼에 대해 구 파일과 레코드 파일에 **서로 다른** 값이 있는 상태,
- **When** `getOriginalIme`을 호출하면,
- **Then** 레코드 파일의 값이 반환된다(REQ-008 조회 규칙 1단계).
- 검증: unit

### AC-IMESTATE-011 — 이관이 순차 반복에 멱등하다
- **Given** 구 파일에 기록 N건이 있는 상태,
- **When** 이관을 유발하는 조회를 **순차로 두 번 이상** 수행하면,
- **Then** 결과가 1회 수행과 동일하고, 기록이 중복되거나 유실되지 않는다.
- **범위 주의 (0.2.0 감사 반영)**: 이 AC는 **순차** 멱등성만 검증한다. REQ-003의 "여러 프로세스가 겹쳐도 결과가 같다"는 주장은 타이밍 검증이 아니라 **구조적 논거**로 성립한다 — 같은 내용을 같은 경로에 배타 생성하므로(REQ-007) 승자가 누구든 최종 상태가 같다. 그 구조적 성질은 AC-021이 판정한다.
- 검증: unit

### AC-IMESTATE-012 — 신규 설치에서 이관 경로가 조용하다
- **Given** 구 파일이 존재하지 않는 상태(신규 설치),
- **When** 조회·기록·삭제를 수행하면,
- **Then** 이관과 관련한 어떤 오류도 발생하지 않고, 구 파일이 새로 생성되지도 않는다.
